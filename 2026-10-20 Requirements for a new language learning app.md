
1. Introduction to the app:
	1. The target of the app is for a native English speaker to learn Chinese, intermediate level.
	2. The focus is on reading text while listening to the accompanying audio at the same time.
	3. Concept: Introduce new words one by one and reuse them frequently after the first time they're introduced, always in new sentences. No flashcards.
	4. New and previously learned words will be incorporated into lessons according to a spaced repetition system. This system will not be as strict as a flashcard app, it is just there to ensure that the user sees new words repeatedly in different contexts until they can read the word fluently.
	5. The lessons in the app will be grouped by topic.
	6. For each topic, the app will have a series of lessons in numerical order. Each lesson will be a short piece of text displayed on the screen, five to ten paragraphs, that is accompanied by fluent, native-sounding AI-generated audio, and translation that is viewable on demand for any given word or sentence.
	7. The app will start off with no topics or lessons. The user will be involved in creating all of the topics and lessons.
	8. There will be two versions of the app: a desktop version for Windows and Linux and an android app
		1. The desktop version of the app will allow the user to create new topics and new lessons, including both text and audio, and manage the word lists. 
		2. Both versions of the app will allow the user to display any lesson text and play the audio to review the lessons. 
		3. It should be possible to sync all of the data (text and audio) to the android version of the app so that lesson review is available offline.
		4. Lesson review data can be synced from the Android app back to the desktop version. 
2. External language models with OpenAI-compatible API
	1. Text to speech model: The app will use an external text to speech model to generate the audio and save it to MP3. The user should be able to configure the URL, and API key if necessary, for the text-to-speech model.
	2. Sentence generation model: The app will use an external LLM to generate sentences and paragraphs containing the appropriate words. The user should be able to configure the URL, and API key if necessary, for the sentence generation model.
	3. Translation model: The app will use an external translation model to generate definitions, translations, and pinyin for all words and sentences and save them to its database. The user should be able to configure the URL, and API key if necessary, for the translation model. 
3. Back-end database. 
	1. New word list: The app will maintain a running new word list which are words that are going to be incorporated into future lessons. These new words will be added by the user as described below.  In time, each new word will eventually be used in a lesson, and then it will be moved to the learned word list. Each new word can be associated with one or more topics.
	2. Learned word list: The app should keep a running list of all the learned words that have already been used in lessons, which topic they belong to, which lessons they have been used in, and a spaced repetition value, which represents how soon they should be incorporated into a future lesson. These words should also be accompanied by their definition and pinyin.
	3. Basic word list: The app should also keep a list of basic words that are simple, the user already knows them, and they may have been used in lesson text before, even though they were never a new word. The user will have the option to move these to the new word list manually if the user doesn't know them after all. These words are also accompanied by their definition and pinyin. 
	4. HSK Word list: The app will contain all vocabulary words from all six levels of the HSK. The user will have the option to review the words in these lists in order and move them to the new word list or the basic word list. Once they are incorporated into one of the other word lists of the app, they should be updated in the HSK word list to indicate where they are being used in the app. 
	5. Sentence list: The app should keep a list of all the sentences used in all the lessons, each of which is accompanied by its translation as a whole sentence, and the audio of that sentence. 
	6. Lesson list: The app should keep a list of lessons. Each lesson is associated with a topic. Each lesson has a list of new words that are introduced for the first time in this lesson.  Each lesson also has a list of previously learned words that are being reviewed in this lesson.  The app should keep track of when each lesson was reviewed. 
	7. Topic list: The app should keep a list of topics. Topics are generated by the user. Each topic is associated with a list of lessons in order. 
4. Adding new words to the new word list: there are 5 ways to do this:
	1. From a piece of text. 
		1. It should be possible to paste some text into a text field.
		2. The app will parse the text into words using a standard prompt and the sentence generation model.
		3. The user can mark which words in the text are new words.
		4. All the marked words will go into the new word list. 
		5. All the rest of the words in the pasted text will be added to the basic word list.
	2. One by one. 
		1. The user can enter new words manually onto the new word list. 
	3. From an existing lesson
		1. It should be possible to mark a word in a lesson as a new word and add it to the new word list so that it will be incorporated into future lessons according to the spaced repetition system. 
	4. Moved over from the basic word list. 
		1. The user can move words from the basic word list to the new word list if they decide they don't know that word after all. 
	5. From the HSK series vocabulary word lists:
		1. The app will contain all vocabulary lists from the HSK series of Chinese language exams.
		2. The user can clearly see which words from these HSK lists have not been used in lessons in the app yet. 
		3. The user will be able to review the words in these lists and add them to either the basic word list or the new word list, one at a time or in bulk. 
5. Contents of a single lesson
	1. Each lesson will introduce five to ten words from the new word list, selected by the user, or suggested by the app. 
	2. There should only be one new word introduced per sentence. It is not necessary for every sentence to have a new word in it. 
	3. New words introduced in previous sentences should be repeated multiple times throughout the rest of the lesson.
	4. The last paragraph of the lesson will not introduce any new words, but instead will contain all of the new words that were introduced in that lesson.
	5. Given all these constraints, it is not really necessary that all of the text of any given lesson makes a coherent essay or story. Each sentence must make sense by itself. Hopefully each paragraph is also somewhat coherent. 
6. Creating a new lesson on the desktop version of the app:
	1. The user will select a topic and then choose to create a new lesson.
	2. Word list for the lesson:
		1. The user will select five to ten new words from the new word list to introduce in this lesson. The app can automatically suggest some new words and the user can either change the selection or just approve the recommended selection. 
		2. The app will also suggest some words from the learned word list (mainly learned words from the same topic) to use in this lesson based on their spaced repetition values. The user can make some changes to this list if needed.
	3. I am not sure whether this app should generate content for the lesson one sentence at a time or one paragraph at a time or even the whole text at once.
	4. Generating the sentences or paragraphs of the lesson:
		1. For each sentence/paragraph, the app will select a few words to use: a maximum of one new word per sentence from this lesson that is being used for the first time, new words from this lesson that were used previously in the lesson, and words from previous lessons that are also going to be used in this lesson. 
		2. The app will write a prompt based on a standard template, the list of words to use, the list of words from the basic word list that can be used optionally, and other requirements for the sentence/paragraph.
		3. The app will execute the prompt on the sentence generation model to generate each sentence/paragraph of the lesson. 
	5. It should be possible for the user to view and edit the sentence/paragraph generation prompt template inside the desktop app. 
	6. After getting the generated sentence/paragraph from the sentence generation model, the app should parse the text and keep track of how many of the requested words were used, and then use this information to generate the list of words for the next sentence/paragraph so that all of the words for the lesson are used at an appropriate cadence over the course of the lesson. 
	7. The last paragraph should not contain any new words for used for the first time. All of the new words for this lesson should be used in the last paragraph. All of the words in the last paragraph should have been used either previously in that lesson or in a previous lesson of the topic.  
	8. Once the entire text of the lesson has been generated, the user will check the text and either request changes to the word list (after which the app will re-generate all the text of the lesson) or approve the lesson text and save the lesson. 
	9. Saving the lesson: 
		1. Once the text of the lesson is approved, the app will generate the audio for that lesson using the text to speech model.
		2. The app will also generate whole sentence translation for all the sentences in the lesson using the translation model. 
		3. All of the new words used in this lesson will be moved from the new word list to the learned word list, and the definition and pinyin will be added, and their usage and spaced repetition values will be updated. 
		4. The spaced repetition values of all of the previously learned words used in this lesson will also be updated in the learned word list. 
		5. All of the sentences will be added to the sentence list. 
		6. The lesson will be added to the topic list, etc. 
7. Topics.
	1. The lessons are organized into topic folders, in a linear order.
	2. The user can create a new topic and start a new chain of lessons.
	3. All of the new words from each lesson should be used in subsequent lessons of that topic according to the spaced repetition system.
	4. It is not necessarily required that new words from one topic are also subsequently used in lessons from a different topic, but it is allowed if appropriate.
	5. The topics themselves are in a numerical order.
8. Main interface. 
	1. When the user opens the desktop app, they will have the following options:
		1. Select a topic and review a lesson in that topic
		2. Create a new topic
		3. Create a new lesson in a topic
		4. Add words to the new word list. 
		5. Review the lists of new words, learned words, basic words and HSK words, and move words between these three lists if needed.
		6. Review and edit the prompt templates, URLs, and API keys  for the various models.
		7. Review and edit the parameters of the spaced repetition algorithm.
		8. Sync data with the Android app. 
	2. When the user opens the Android app, they only have the following options:
		1. Select a topic and review a lesson in that topic
		2. Sync data with the desktop app. 
9. Reviewing a lesson
	1. First, the user can select a topic. The app will display a list of lessons in that topic. It will indicate when each lesson was last reviewed or if it has never been reviewed. 
	2. The user can select a lesson to review
	3. During the review, the app will display the text of the lesson and play the audio accompanying that lesson.
	4. The very first time a new word is introduced in that lesson, it should be highlighted to indicate to the user that it is a new word
	5. Every word in every sentence should be clickable/tappable to show/hide the translation of the word, the pinyin, whether it is on the learned word list or not, whether it is on the basic word list or not, whether it is on the new word list or not, an option to add it to the basic word list or the new word list if it is not on any list, and an option to move it from the basic word list to the new word list if it is on the basic word list. 
	6. There should be an option to view the whole translation of any given sentence. 
	7. It should be possible to play, pause and restart the audio of the lesson, change the audio speed, jump forward or back by 15 seconds, jump to the end of the audio to go to the word review stage below.
	8. Word review: After all of the audio of the lesson has been played, the user will see a list of words in this lesson that are on the Learned Word List. The user can optionally mark any of these words "difficult", "easy", "standard", or "unchanged". "Standard" is the default option. The user can multi-select words on the list (or select all) and mark them in bulk. 
		1. For words marked "difficult", the spaced repetition value should be decreased so that they will be incorporated in a future lesson quite soon.
		2. For words marked "easy", the spaced repetition value should get an extra increase so that they won't be incorporated in a future lesson very soon.
		3. For words marked "standard", the spaced repetition value should be increased by the standard amount according to the spaced repetition algorithm parameters.  
		4. For words marked "unchanged", the spaced repetition value should not change at all.  
	9. After word review, the user can mark the lesson review complete and return to the list of lessons or go on to the next lesson in the topic. The database should be updated to show that this lesson has been reviewed at this time. 
	10. Alternatively, the user can cancel out of the lesson review, and no changes will be made to the database.

---

## 1. Overview & Goals

### 1.1 Purpose
A language-learning application for a **native English speaker learning Chinese at an intermediate level**, focused on **reading text while listening to accompanying audio at the same time**.

### 1.2 Learning philosophy
- New words are introduced **one at a time** and then **reused frequently in new contexts** (always in new sentences) until they can be read fluently.
- **No flashcards.** Acquisition happens through exposure in lesson text.
- Word scheduling follows a **spaced repetition system (SRS)** that is intentionally *not strict*: it exists only to ensure the user encounters new words repeatedly in varied contexts until fluent.
- The app starts **empty** — no topics or lessons. The user creates all content, assisted by AI generation.

### 1.3 High-level workflow
1. The user adds words to a **New Word List** (from pasted text, manual entry, existing lessons, the Basic Word List, or HSK vocabulary lists).
2. On the desktop app, the user creates lessons within a **Topic** that introduce 5–10 new words, review recently-learned words per SRS values, and are generated by an external LLM using editable prompt templates.
3. Audio is generated via an external text-to-speech model (MP3); translations, definitions, and pinyin come from an external translation model.
4. The user reviews lessons (text + audio, with tap-to-look-up words), then rates learned words (difficult / easy / standard / unchanged) to update SRS values.
5. Data (text + audio + review state) syncs bidirectionally between the desktop app and the Android app.

## 2. Glossary

| Term | Definition |
|---|---|
| **Topic** | A user-created grouping of lessons, arranged in a linear numerical order (e.g., "Cooking", "Travel"). |
| **Lesson** | A short text (5–10 paragraphs) within a topic, with accompanying audio and on-demand translations. Introduces 5–10 new words. |
| **Sentence** | The atomic unit of lesson text. Stored with its whole-sentence translation and its word segmentation (no separate per-sentence audio; see D-1). |
| **New Word** | A word queued to be introduced in future lessons. Lives on the **New Word List**. |
| **Learned Word** | A word that has appeared in at least one saved lesson. Has definition, pinyin, topic/lesson usage history, and an SRS value. |
| **Basic Word** | A word the user already knows. May appear in lesson text freely. Can be promoted to New Word List. |
| **HSK Word** | A word from the bundled HSK levels 1–6 vocabulary lists, tracked for whether/how it is used in the app. |
| **SRS value** | A per-word value representing how soon the word should be incorporated into a future lesson. User-configurable parameters. See §11. |
| **Sentence Generation Model** | External OpenAI-compatible LLM used to generate lesson sentences/paragraphs. |
| **Translation Model** | External OpenAI-compatible model used for definitions, translations, and pinyin. |
| **TTS Model** | External OpenAI-compatible text-to-speech model producing MP3 audio. |

## 3. Platform Scope

Two applications share one data model and one database format.

### 3.1 Desktop app (Windows and Linux)
Full authoring environment. Capabilities:
- Create, edit, and delete topics.
- Create lessons (word selection, AI text generation, review, approval, saving) — see §7.
- Add words to the New Word List (all five flows) — see §5.
- Browse and manage New / Learned / Basic / HSK word lists; move words between lists.
- Edit prompt templates, model URLs, and API keys — see §9.
- Review lessons — see §8.
- Edit spaced-repetition algorithm parameters — see §11.
- Sync data with the Android app — see §10.
- Review lesson history (when each lesson was last reviewed).

### 3.2 Android app
Review-only environment. Capabilities:
- Select a topic and review a lesson in it — see §8 (same review features, adapted to touch).
- Sync data with the desktop app (full download of text and audio for **offline review**; upload of lesson-review results) — see §10.
- The Android app **cannot** create or edit topics, lessons, or word lists, and cannot configure models.

### 3.3 Non-goal
Multi-user, accounts, or cloud hosting of content are not required. This is a single-user, local-first application.

## 4. Data Model (Logical)

The desktop app is the source of truth. All entities below live in a single local database. (Physical schema and storage technology are decided in the desktop-app design phase.)

### 4.1 Topics
- `id`, `name` (user-created), `order index` (topics are in numerical order).
- A topic owns an ordered list of lessons.
- Deleting a topic is **blocked while the topic contains lessons** (D-9); the user must delete or move its lessons first.

### 4.2 Lessons
- `id`, `topic id`, `order index` within the topic.
- `title` (optional, for display).
- Ordered list of sentences (the lesson text, 5–10 paragraphs).
- `new words` — list of words **introduced for the first time** in this lesson (5–10 words).
- `review words` — list of previously-learned words being reviewed in this lesson.
- `audio` — **exactly one MP3 file for the whole lesson** (D-1). Per-sentence audio files are **not** stored (this deliberately deviates from the original description §3.5, which mentioned per-sentence audio; the whole-lesson MP3 supersedes it).
- `last reviewed timestamp` (or "never reviewed").
- `date created`.

### 4.3 Sentences
- `id`, `lesson id`, `paragraph number`, `position within paragraph`.
- `text` (Chinese, unsegmented) **and its stored word segmentation** (D-5: produced by a local segmentation library with LLM fallback; hand-editable — see §7.8).
- `translation` (whole-sentence English translation).
- Each word token in the sentence links to a word entry (New / Learned / Basic / HSK / unlisted).

### 4.4 Words

A word is identified by its Chinese written form (**simplified Chinese only**, D-10). Four logical lists, modeled as a single word entity with a `list membership` state (a word is on exactly one of: New, Learned, Basic; HSK membership is a separate flag):

| List | Key fields |
|---|---|
| **New Word List** | word (Chinese), definition, pinyin, associated topic(s) (one or more), date added, source (paste/manual/lesson/basic/HSK), order added |
| **Learned Word List** | word, definition, pinyin, topic(s), lesson usage history, SRS value (see §11) |
| **Basic Word List** | word, definition, pinyin, date added, source |
| **HSK Word List** | word, definition, pinyin, HSK level (1–6), app status: unused / on new list / on basic list / learned |

Rules:
- When a new word is used in a saved lesson, it **moves** from the New list to the Learned list, gaining definition, pinyin, usage history, and an initial SRS value.
- A word can be associated with **one or more topics**.
- HSK entries are **reference data**; they are updated only to reflect where a word is used in the app, never removed.
- Moving words between lists is supported: Basic→New, HSK→New, HSK→Basic, and New→Basic (mistake fix). Learned→New is **not** supported (a learned word can instead be rated "difficult" to come back sooner).

### 4.5 Settings & templates
- Model configuration: base URL, API key (optional), model name, and request parameters for each of the three models (sentence generation, translation, TTS).
- Prompt templates (editable in-app): text parsing template (§5.1), sentence/paragraph generation template (§7.4), translation template, and any standard system prompts.
- SRS parameters (see §11).
- Sync configuration (see §10, D-3: USB export/import with integrity checks and backups).

## 5. Adding Words to the New Word List

There are five supported flows. All five are desktop-only.

### 5.1 From a piece of pasted text
1. The user pastes text into a text field.
2. The app parses the text into words using a **local segmentation library** (e.g., jieba, with the app's own word lists loaded as a custom dictionary so app words are always segmented as single words), falling back to a **standard prompt** sent to the sentence generation model when local segmentation is ambiguous or fails (D-5).
3. The app displays the parsed words; the user marks which ones are new words.
4. All marked words are added to the **New Word List**.
5. All remaining (unmarked) words in the text are added to the **Basic Word List**.
   - Words already on any list are not duplicated; existing membership wins.
   - Unlisted words that the user neither marks as new nor wants in Basic may be skipped (user choice; default: all unmarked words go to Basic per the source description).

### 5.2 One by one (manual entry)
The user types a word directly into the New Word List. Definition and pinyin are filled in by the translation model (on demand or automatically — see §9.3).

### 5.3 From an existing lesson
While reviewing a lesson, the user can tap any word and mark it as a new word; it is added to the New Word List and will be scheduled into future lessons via the SRS.

### 5.4 Moved from the Basic Word List
The user can move any Basic word to the New Word List if they realize they don't actually know it. Available in the word-list management views (§8.1 desktop main menu) and from the lesson-review word popup (§8.5).

### 5.5 From the HSK vocabulary lists
- The app bundles **all vocabulary from HSK levels 1–6** (D-7: the user has no HSK file; a public HSK dataset will be sourced, downloaded, verified, and bundled into the app during development).
- The HSK browser clearly shows which words have **not** been used in the app yet.
- The user reviews words level by level, in order, and adds them to the **New Word List** or the **Basic Word List**, one at a time or **in bulk** (multi-select).
- Once a word is incorporated into another list, its HSK entry is updated to show where it is used in the app.

<!-- Section 6 -->
## 6. Lesson Content Rules

These rules constrain how the sentence generation model is prompted and how generated text is validated.

1. Each lesson introduces **5–10 words from the New Word List**, selected by the user or accepted from an app suggestion (§7.2).
2. There is at most **one brand-new word per sentence**. Not every sentence needs a new word.
3. Words introduced earlier in the lesson **must be repeated multiple times** throughout the rest of the lesson.
4. The **last paragraph** introduces no new words; instead it **contains all of the new words** introduced in that lesson. Every word in the last paragraph must have been used either earlier in this lesson or in a previous lesson of the topic.
5. Individual sentences must make sense on their own. Paragraph-level coherence is desirable but not required; lesson-level narrative coherence is explicitly **not** required.
6. Lesson length: **5–10 paragraphs**.
7. Optionally, Basic words may be used freely in lesson text (they are known vocabulary).

## 7. Creating a New Lesson (Desktop)

### 7.1 Entry point
The user selects a topic and chooses "Create new lesson". (Creating a new topic is a separate flow: name it, and it becomes an empty ordered container for lessons.)

### 7.2 Word selection for the lesson
**New words (5–10):**
- The app **suggests** new words: **oldest-added first**, preferring new words associated with this topic, then any remaining oldest-added new words (D-11).
- The user can change the selection or approve the suggestion as-is.

**Review words (previously learned):**
- The app **suggests** learned words — primarily learned words from the **same topic** — ranked by their SRS values (most-due first).
- The user can adjust this list.

### 7.3 Generation granularity
The lesson text is generated incrementally — **one paragraph at a time** (D-12) — rather than as one whole-text request, so the app can track which requested words were actually used and steer the next request. If paragraph-level prompts prove unable to produce good text, the plan is to switch to **one sentence at a time**; the generation unit will be a switchable setting either way.

### 7.4 Prompt construction
For each sentence/paragraph request, the app builds a prompt from:
- The **editable standard template** (§4.5, viewable/editable in-app).
- The words to use in this unit:
  - at most **one first-use new word** from this lesson,
  - new words from this lesson already used earlier in the lesson (for repetition),
  - previously-learned words being reviewed in this lesson.
- The list of **Basic words** that may be used optionally.
- Other requirements: at most one new word, sentence/paragraph rules from §6, style constraints.

### 7.5 Execution
The app executes the prompt against the **sentence generation model** and receives the generated Chinese text.

### 7.6 Usage tracking and cadence
- After each generated unit, the app parses the text into words, determines which of the requested words were actually used, and updates a running tally.
- This tally drives the word selection for the **next** unit so that all lesson words appear at an appropriate cadence, satisfying §6 rules (repetition of earlier new words; no first-use new words after the final paragraph begins; final paragraph contains all new words).

### 7.7 Final paragraph
The last paragraph is generated under special constraints: no first-use new words; **all** of the lesson's new words must appear; all words must have been used earlier in this lesson or in previous lessons of the topic.

### 7.8 Review, revise, approve
- Once the full lesson text is generated, the user reviews it.
- Options: **request word-list changes** (the app then regenerates the **entire** lesson text), **hand-edit the text** (D-6: add/remove/edit sentences and paragraphs; also hand-correct the stored word segmentation wherever the automatic segmentation is wrong), or **approve and save**.
- Audio is always generated from the **final approved text**, so hand edits are automatically reflected in the audio; no separate audio-regeneration step is required.

### 7.9 Saving the lesson (pipeline)
On approval, the app performs, in order:
1. **Audio generation**: generate **one MP3 for the entire lesson** from the final approved text via the TTS model (D-1).
2. **Sentence translations**: generate whole-sentence translations for every sentence via the translation model.
3. **Word promotion**: move the lesson's new words from the New Word List to the Learned Word List; add definition and pinyin (via translation model); record usage; set initial SRS values.
4. **SRS updates**: update SRS values for all previously-learned words used in this lesson.
5. **Sentence list**: add all sentences (text, segmentation, translation) to the sentence list.
6. **Lesson registration**: add the lesson to the topic's ordered lesson list, with its new-word and review-word lists.

All steps are atomic to the extent practical: a failure mid-pipeline (e.g., TTS error) leaves the lesson in a clearly-marked incomplete state with a retry/resume option, rather than corrupting the word lists.

## 8. Reviewing a Lesson (Desktop and Android)

### 8.1 Lesson selection
1. The user selects a topic; the app displays the topic's lessons in order, indicating **when each was last reviewed** (or "never reviewed").
2. The user selects a lesson to review.

### 8.2 Text and audio display
- The lesson text is displayed, and the audio plays alongside it.
- The first occurrence of each new word in the lesson is **statically highlighted** to flag it as new. There is **no karaoke-style real-time word highlighting** synced to audio playback (D-1); the user follows along by themselves.

### 8.3 Word interaction (tap/click)
Every word in every sentence is clickable/tappable, showing/hiding a popup containing:
- the word's **translation/definition** and **pinyin**;
- its list status: on the Learned list, on the Basic list, on the New list, or on none;
- if not on any list: options to **add it to the Basic list** or the **New list**;
- if on the Basic list: an option to **move it to the New list**.

### 8.4 Sentence translation
An option to view the whole translation of any given sentence (on demand, per sentence).

### 8.5 Audio playback controls
- Play, pause, restart.
- Change playback speed.
- Jump forward / back **15 seconds**.
- Jump to the end of the audio → proceeds to the word review stage.

### 8.6 Word review (post-audio)
After all lesson audio has played, the app shows the list of words in this lesson that are on the **Learned Word List**. For each word the user may mark:
- **difficult** — SRS value decreased so the word returns in a future lesson quite soon.
- **easy** — SRS value gets an extra increase so it won't return soon.
- **standard** (default) — SRS value increased by the standard amount per SRS parameters.
- **unchanged** — no change.

Multi-select (and select-all) with bulk marking is supported.

### 8.7 Completing the review
- After word review, the user can **mark the review complete** and return to the lesson list or continue to the **next lesson in the topic**. The database records this lesson's review timestamp.
- Alternatively the user can **cancel out of the review**, in which case **no changes are made to the database** (no SRS changes, no review timestamp, no word-list additions made during that review session — with the explicit exception of actions the user confirmed during word popups, e.g., marking a word as new; those are committed immediately when performed, and canceling the lesson review does not undo them).

## 9. External Model Integration

All three integrations use an **OpenAI-compatible API**. For each, the user can configure the **URL** and the **API key** (when necessary), plus the model name and relevant parameters. All configuration is editable in-app (§3.1).

Planned providers (D-4):
- **TTS:** self-hosted **Kokoro v1** running in Docker on the user's other machine (OpenAI-compatible endpoint).
- **Sentence generation & translation:** local models served by **LM Studio** (a Qwen 9B-class or Gemma 12B-class model), OpenAI-compatible.
- **Fallback for the two text tasks:** **Alibaba Cloud**'s OpenAI-compatible endpoint (already in use for this project), if the local models prove not capable enough.
- LM Studio and Kokoro run on a different machine than the desktop app, so all endpoint URLs must be reachable over the network and configurable at runtime.

### 9.1 Sentence generation model
- Used for: parsing pasted text into words (§5.1) and generating lesson sentences/paragraphs (§7).
- Prompts are built from editable templates (§4.5, §7.4).

### 9.2 Translation model
- Used for: word definitions, word translations, pinyin, and whole-sentence translations (§7.9 step 2, §5.2).
- Results are saved to the database.

### 9.3 TTS model
- Used for: generating lesson and sentence audio (§7.9 step 1), saved as **MP3**.
- Voice/speed and other parameters are configurable.

### 9.4 Failure handling
- Network/API errors surface clearly with retry options; no partial silent failures.
- Rate/cost considerations: generation pipelines show progress and are resumable (§7.9).

## 10. Desktop ↔ Android Sync

- **Direction 1 (desktop → Android):** all lesson data — text and audio — syncs to the Android app so lesson **review is available offline**. This includes topics, lessons, sentences (text + translations), audio (MP3), word lists needed for review (learned/basic/new status, definitions, pinyin).
- **Direction 2 (Android → desktop):** lesson **review data** syncs back: review timestamps and word review ratings (difficult/easy/standard/unchanged), plus any word-list actions taken during review on Android (e.g., promoting a Basic word to New, marking a lesson word as new).
- The desktop app is the **source of truth**; sync merges Android-side review changes into the desktop database.
- **Mechanism (D-3):** sync over a **USB cable**, implemented as a guided **export/import** flow: the desktop app writes a sync bundle to the connected Android device (or a file the user copies to it), and reads back a results bundle produced by the Android app. The sync function must guarantee **data integrity** (bundle manifest with checksums; corrupt or partial bundles are rejected before anything is applied) and must **create automatic backups** of both databases before applying sync changes, so a bad sync can be rolled back.
- Conflict rules: reviews performed on Android are queued and reconciled by timestamp on the desktop; conflicting SRS updates resolve to the most recent rating.

<!-- Section 11 -->
## 11. Spaced Repetition System

- Purpose: ensure the user sees words repeatedly in different contexts until they read them fluently. **Intentionally less strict than a flashcard app.**
- Every learned word carries an **SRS value** representing how soon it should be incorporated into a future lesson (smaller/earlier = due sooner).
- SRS values are updated when:
  - a new word is promoted to Learned (initial value);
  - a learned word is used in a lesson being created/saved (§7.9.4);
  - the user rates words during lesson review (§8.6): difficult (decrease), easy (extra increase), standard (standard increase), unchanged (no change).
- **Algorithm (D-2):** an **Anki-like SM-2 variant** — per-word easiness factor and interval, with all parameters (initial interval, easy/difficult multipliers, interval bounds) **user-configurable in-app** (desktop main menu §12.1). The four review ratings map to it as follows: **difficult** → interval reset/shortened (relearn-style step); **easy** → larger-than-normal interval growth; **standard** → normal SM-2 interval growth; **unchanged** → no change at all.
- SRS values drive:
  - suggestions of review words when creating a lesson (§7.2);
  - (optionally) reuse of a topic's learned words in subsequent lessons of that topic (§13.3).

## 13. Topics

1. Lessons are organized into topic folders, in a linear (numerical) order.
2. The user can create a new topic and start a new chain of lessons.
3. New words from each lesson are used in **subsequent lessons of that topic** according to the spaced repetition system.
4. Reusing new words from one topic in lessons of a **different** topic is allowed when appropriate, but not required.

## 14. Non-Functional Requirements

- **Offline-first review:** lesson review (text + audio) works with no network on both platforms; only authoring and generation require network.
- **Audio format:** MP3.
- **Single user, local data:** no accounts; data stored locally on desktop; Android holds a synced copy.
- **Cross-platform:** desktop runs on Windows and Linux with the same codebase; Android app is a separate codebase sharing the data model.
- **Data safety:** database and audio files are user-accessible/backupable; sensible failure states for interrupted generation (§7.9, §9.4).
- **Chinese text specifics:** simplified Chinese only; robust word segmentation stored with sentences (§4.3, D-5); pinyin displayed for words.
- **Technology constraint (D-8):** use **Python as much as possible** across the project. The desktop app is pure Python; the Android app is planned as **Flutter** (user's prior experience; see `20261101_android_app_plan.md`), since Python is not practical for a touch-first Android UI.

## 15. Decisions (v1.1 — all Open Questions resolved 2026-11-01)

- **D-1 Audio & highlighting:** Exactly **one MP3 per lesson**; no per-sentence audio files. **Static** new-word highlighting only; **no karaoke-style real-time highlighting** — the user follows along by themselves.
- **D-2 SRS algorithm:** **Anki-like SM-2 variant** (easiness factor + interval per word, configurable parameters). Ratings: difficult → shortened/reset interval; easy → extra interval growth; standard → normal growth; unchanged → no change.
- **D-3 Sync:** Over **USB cable**, as a guided export/import with **data-integrity verification** (checksums) and **automatic pre-sync backups** on both sides.
- **D-4 Model providers:** TTS = self-hosted **Kokoro v1** (Docker, OpenAI-compatible). Text generation/translation = local models via **LM Studio** (Qwen 9B-class or Gemma 12B-class). Fallback = **Alibaba Cloud** OpenAI-compatible endpoint.
- **D-5 Segmentation:** **Local library (jieba) primary**, with the app's word lists as custom dictionary; **LLM as fallback**; segmentation **stored per sentence** and **hand-editable**.
- **D-6 Manual lesson editing:** **Allowed** — user can hand-edit generated text (and segmentation) before saving; audio is generated from the final approved text.
- **D-7 HSK data:** No user file exists; the app will **source, download, verify, and bundle** a public HSK 1–6 dataset during development.
- **D-8 Technology:** **Python as much as possible** across the project; desktop app is pure Python.
- **D-9 Topic deletion:** **Blocked** for non-empty topics.
- **D-10 Script:** **Simplified Chinese only.**
- **D-11 New-word suggestions:** **Oldest-added first** (topic-associated words preferred, then remaining oldest).
- **D-12 Generation unit:** **One paragraph at a time** by default; if prompt quality is poor, switch to one sentence at a time (unit stays a setting).
